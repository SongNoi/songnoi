# ADR 0003 — Internationalisation

Status: Accepted · Date: 2026-11-04 · Work item: `000-foundation`

## Context

SongNoi is open source for a global audience and Thai-first in spirit. The owner asked for a
multilingual UI from day one. Respondents should see the UI around a form in the language of
that form, not in whatever their browser prefers.

## Decision

- `next-intl` without locale URL prefixes. Locales `en` and `th`; default `en`.
- Messages in `apps/web/messages/{en,th}.json`, namespaced `common.*`, `admin.*`,
  `respond.*`. A unit test fails if the two files do not have identical keys or a message
  is empty.
- **Admin locale:** the `songnoi_locale` cookie, set by the public `setLocale` Server Action.
- **Respondent locale:** `resolveRespondentLocale(formLocale)`; `Accept-Language` is ignored.
- **Two root layouts** — `app/(admin)/layout.tsx` and `app/(respond)/layout.tsx` — so each
  world owns its `<html lang>`. A single root layout could only read the admin cookie.
- **Thai typography:** Kanit, bundled as WOFF2 (SIL OFL, licence in `src/app/_fonts/`) and
  loaded with `next/font/local`; Thai line-height 1.75.

## Consequences

- No runtime or build-time font CDN: builds work offline and behind TLS-intercepting proxies
  (the original `next/font/google` choice failed exactly there).
- **Form content is single-language** (amended 2026-11-05, owner decision for `001`): a Form
  Schema records one BCP 47 `meta.language` and holds every title, label, help text and option
  label as a plain string in that language. There is no `LocalizedText`. Multi-language form
  content would be a later Form Schema format version with a migration step (ADR 0012), not a
  non-breaking addition.
- The respondent locale comes from the form: `resolveRespondentLocale(meta.language)`. A region
  tag such as `th-TH` should resolve to `th`; unsupported languages fall back to `en` (`005`).
- `@songnoi/schema` has no user-facing strings: validation errors are codes plus params
  (ADR 0012), mapped to `messages/{en,th}.json` by the renderer (`002`) and the respond flow
  (`005`).
- Every new UI string needs an entry in both message files.
